# Steel Tools India — Catalogue & Enquiry Website

Product catalogue and enquiry website for **Steel Tools India, Kolkata — Since 1957**.
Visitors find a tool, pick the exact size, and send an enquiry on **WhatsApp** or **email**.
There is deliberately **no cart, no checkout and no prices** anywhere on the site.

- Angular 20 (standalone components, signals, OnPush, lazy routes)
- Every page is **prerendered to static HTML** (591 product pages + 6 site pages), then hydrated in the browser
- Hosts on any static web host — no server code, no database

---

## Quick start

```bash
npm install
npm start            # dev server → http://localhost:4200
npm run build        # production build → dist/steel-tools-india/browser  (upload this folder)
npm run test:ci      # unit tests (headless Chrome; set CHROME_BIN if Chrome isn't on the PATH)
npm run validate     # catalogue data checks: unique slugs, images exist, no price-like data
```

`npm run build` first runs `scripts/generate-seo-files.mjs`, which writes `public/sitemap.xml` and
`public/robots.txt` from the catalogue and the site address in `company.config.ts`.

---

## Before going live — checklist

1. **Set the real domain** in `src/app/config/company.config.ts` → `siteUrl`
   (used for the sitemap, robots.txt, canonical links, link previews and structured data). Then rebuild.
2. Confirm the **WhatsApp number** (currently the same as the phone number).
3. Upload the contents of `dist/steel-tools-india/browser/` to the host and set the fallback (below).
4. Submit `https://<your-domain>/sitemap.xml` in Google Search Console.

## Hosting

The build output is plain static files:

```
dist/steel-tools-india/browser/
  index.html                      ← home page (prerendered)
  index.csr.html                  ← app shell, for URLs that aren't prerendered (e.g. 404s)
  products/index.html
  products/<product-slug>/index.html   (one per product)
  categories/  about-us/  contact/  get-a-quote/
  assets/  *.js  *.css  sitemap.xml  robots.txt  _redirects  .htaccess
```

Serve files and folders as they are; send every **other** URL to **`/index.csr.html`** (not `/index.html`,
which is the prerendered home page). Enable gzip/brotli compression — the host usually does this by default.

| Host | What to do |
|---|---|
| Netlify / Cloudflare Pages | Nothing — `_redirects` is included. |
| Apache / cPanel shared hosting | Nothing — `.htaccess` is included (needs `mod_rewrite`). |
| Nginx | `location / { try_files $uri $uri/index.html /index.csr.html; }` |
| Firebase Hosting | `"rewrites": [{ "source": "**", "destination": "/index.csr.html" }]` |
| Vercel | `vercel.json`: `{ "rewrites": [{ "source": "/(.*)", "destination": "/index.csr.html" }] }` (static files are served first) |

## Editing content

| What | Where |
|---|---|
| Phone, WhatsApp, email, address, **business hours**, **owner**, site address | `src/app/config/company.config.ts` — the only place to change these |
| Navbar items | `src/app/config/navigation.config.ts` |
| Products per page (12), sort options | `src/app/config/catalogue.config.ts` |
| Categories (name, description, icon) | `src/app/data/categories.ts` |
| Products | `src/app/data/products/*.ts` — one file per supplied catalogue (see below) |
| Product photos | `public/assets/products/<category>/<slug>.webp` |
| About Us wording (incl. the owner section) | `src/app/pages/about/about.html` |
| Colours, type, spacing | `src/styles/_variables.scss` |

### Adding or editing a product

Products live in `src/app/data/products/`:

| File | Source catalogue |
|---|---|
| `rr-2026.ts` | R★R Brand supplementary list (2026) |
| `rr-2025.ts` | R★R Brand machine tools accessories master list (2025) |
| `rr-centres.ts` | R★R Brand revolving & dead centres (2025 + 2026) |
| `rr-ht.ts` | R★R Brand hand tools & punches list (01-06-2026) — page 3 only |
| `rr-ct.ts` | R★R Brand carbide cutting tools (2026) |
| `miranda.ts` | Miranda products list (2026) |
| `taparia.ts` | Taparia Tools price list (April 2026) — generated by `scripts/taparia/gen_taparia.py` |

Each product has a `slug` (its web address), `name`, `category`, `subcategory` (the "type" filter), `brand`,
`summary`, `description`, `images`, `specifications`, and a size table (`variantAxes` + `variants`).
The helpers in `src/app/data/variant-builders.ts` (`single`, `cross`, `rows`) build size tables from catalogue rows.

Rules the data follows: **no prices**, nothing that isn't in the supplied catalogues, and anything uncertain gets a
`reviewNote` (never shown on the site; listed in `docs/catalogue-analysis.md`). Run `npm run validate` after editing.

To add a photo: save a transparent `.webp` (about 900 px on the long side) to
`public/assets/products/<category>/<slug>.webp` and add it to the product's `images` list.
Products without photos show a clean category placeholder. `scripts/images/` has the cut-out tools used so far.

## How the site is put together

```
src/app/
  config/        company, navigation and catalogue settings
  data/          categories + product files (loaded lazily as one chunk)
  models/        Product / Category types (no price fields)
  services/      ProductService (load/search/filter), EnquiryService (WhatsApp/email text),
                 SeoService + SiteTitleStrategy (titles, meta, canonical, JSON-LD)
  components/    header, footer, product-card, product-image, product-gallery, variant-selector,
                 enquiry-panel, enquiry-buttons (WhatsApp / Email), quote-form, pagination, product-filters,
                 breadcrumbs, business-hours, category-card, page-intro, empty-state, skeletons, icons
  pages/         home, products, product-detail, categories, about, contact, quote, not-found
  app.routes.ts          browser routes (lazy)
  app.routes.server.ts   which routes are prerendered
src/styles/      design tokens, mixins, animations (incl. reduced motion), base styles
scripts/         SEO file generator, catalogue validator, image and data extraction helpers
docs/            catalogue analysis, per-phase notes and items for client review
```

- **Catalogue state lives in the URL** (`/products?q=&category=&type=&brand=&sort=&page=`), so filters survive refresh,
  links can be shared and Back works. **Exactly 12 products per page**; changing a filter or search resets to page 1.
- **Selected size lives in the URL** (`/products/<slug>?variant=<id>`) and is written into WhatsApp/email messages
  along with a link back to that exact size.
- **Get A Quote** (`/get-a-quote?product=<slug>&variant=<id>`) arrives pre-filled from product pages. There is no
  backend: sending opens WhatsApp or the visitor's email app, and the form says so.
- **Business hours** show a live "Open now / Closed now" line, computed in Kolkata time in the visitor's browser.

## Quality checks (final QA, 1 Oct 2026)

- `ng build`: no errors or warnings; 597 routes prerendered (591 products).
- Unit tests: 20 passing (catalogue integrity & no prices, search/filter, pagination, enquiry messages, business hours, navbar).
- Browser QA on desktop (1440), tablet (820) and mobile (390): all pages, filters, pagination, sizes, enquiries,
  quote form, mobile menu, invalid URLs — no console errors, no horizontal scrolling, no broken images.
- Accessibility: axe-core reports 0 violations on every page; Lighthouse accessibility 100.
- Lighthouse (gzip enabled): Desktop performance 99–100; mobile (simulated slow 4G) 81–87; SEO 100; Best practices 100.
- Reduced-motion preference respected (animations and delays switched off).

Fonts are self-hosted via `@fontsource` (Barlow Condensed, IBM Plex Sans, IBM Plex Mono) — no third-party requests
except the optional Google Map on the Contact page, which loads only when the visitor clicks "Show map".
